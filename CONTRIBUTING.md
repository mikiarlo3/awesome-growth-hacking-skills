# Contributing to Awesome Agentic Growth & Marketing Skills

Thank you for helping build a practical, external-only directory of AI agent skills for marketing, growth, product-led growth, sales, and revenue operations. The standard is simple: every entry should help an operator achieve a legitimate, repeatable outcome without spam, deceptive engagement, or platform-policy evasion.

## What belongs here

|Requirement|What we look for|
|---|---|
|Public and durable|A publicly accessible repository or individual skill with a stable link.|
|Agent-native|A `SKILL.md`, compatible agent-skill package, or clearly documented workflow for Claude Code, Codex, Cursor, Gemini CLI, or another agent environment.|
|Practitioner relevance|A concrete use case in marketing, growth, GTM, product, revenue, research, or operations.|
|Useful description|A short, specific description that explains what the resource does rather than making promotional claims.|
|Responsible execution|No spam, fabricated social proof, fake reviews, account abuse, surveillance, unauthorized scraping, or terms-of-service evasion.|

## What does not belong here

This directory does not accept private repositories, paid-only directories, generic prompt lists with no documented workflow, duplicate forks where an active upstream source exists, or resources designed to automate deceptive or abusive behavior. If a source has moved, please link to the currently maintained upstream repository rather than the archived redirect.

## Add an entry

Choose the most relevant category in `README.md`. Add one Markdown list item, alphabetized by project name within that category, in this format:

```markdown
- [Repository or Skill Name](https://github.com/owner/repository) - Specific, factual description of the workflow or capability.
```

When linking directly to a skill inside a larger repository, use the skill's canonical GitHub path and state its purpose in the description. Do not add tracking links, referral links, shortened URLs, or links that require a login to evaluate.

## Pull request checklist

Before opening a pull request, confirm the following:

- [ ] The resource is public and the URL resolves.
- [ ] It contains an actual agent skill or a documented agent workflow.
- [ ] It fits one of the directory's marketing, growth, product, sales, or operations categories.
- [ ] It is not a duplicate, obsolete redirect, or packaging fork of an already listed active upstream project.
- [ ] The entry is alphabetized and uses a concise, factual description.
- [ ] The resource does not encourage spam, fake engagement, deceptive automation, or terms-of-service evasion.

## Review process

Maintainers review submissions for link health, scope, specificity, source quality, and ethical use. A pull request may be declined when its source is inactive, too broad to be actionable, duplicative, unverified, or misaligned with these standards. Constructive improvements to existing descriptions and corrections to moved links are especially welcome.
